# Vivaldi 案件ワークスペース自動振り分け mod 設計書

Oct 24, 2026 · @Takayuki Mori

## 背景と目的

タブのタイトルとURLに含まれる顧客名で、新しく開いたタブを案件ごとのワークスペースへ自動で移し、同じページの重複は既存タブに寄せる Vivaldi mod を作る。

案件ごとに Salesforce（商談）、Google Slides、Celonis ダッシュボードがセットで開かれ、多いときは40〜60タブになる。メールや Slack のリンクは今アクティブなワークスペースに開くため、案件ワークスペースが混ざり、同じ資料が複数タブで開かれてメモリを食う。

Vivaldi 標準のワークスペースルールは URL（ドメイン）でしか判定できず、案件をまたいで同じドメインを使うこの用途では振り分けられない。タイトルを見ることで、Slides のファイル名や商談名に入っている顧客名を拾える。

効果の狙いは2つ。

1. 案件単位でワークスペースが保たれ、手が離れた案件を丸ごとハイバネートできる
2. 重複タブが減り、メモリ消費が下がる

## 要件

**機能要件**

| ID | 内容 |
| --- | --- |
| F1 | タブが開かれた、または URL / タイトルが変わったときに判定する |
| F2 | タイトルと URL に含まれるキーワードが1つのワークスペースだけに一致したら、そこへ移す |
| F3 | キーワードの既定値はワークスペース名そのもの。設定で別名（英語名、略称、URL の一部）を足せる |
| F4 | 0件一致は何もしない。2件以上一致は動かさず、タイトル先頭に印を付けてログを残す |
| F5 | 移した先に同じページがすでにあれば、新しいタブを閉じて既存タブを前に出す |
| F6 | ユーザーが手で別のワークスペースへ移したタブは、以後自動で動かさない |
| F7 | 移動後に移動先ワークスペースへ切り替えるかは設定で選べる |
| F8 | 一時停止・再開をコマンドで切り替えられる |

**非機能要件**

- 外部通信なし。判定も設定もすべてローカルで完結する
- 判定で体感的な遅延や CPU 負荷を出さない（イベント駆動、ポーリングしない）
- Vivaldi のアップデートで mod が消えても、スクリプト1本で入れ直せる
- 対象は macOS 版 Vivaldi のみ

**スコープ外**

- ウェブパネル、インストールしたアプリ（PWA）のウィンドウ、拡張機能ページ、vivaldi:// の内部ページ
- ピン留めしたタブ
- ワークスペースの自動作成（案件ワークスペースはユーザーが作る）
- ハイバネートの自動化（Memory Saver に任せる）

## 全体アーキテクチャ

Vivaldi の UI 自体が Web 技術で作られており、その HTML（`window.html`、古い版では `browser.html`）に自作 JS を読み込ませるのが mod の仕組み。この JS はブラウザ UI の権限で動き、`chrome.tabs` と Vivaldi 独自の `vivaldi.*` API を使える。`window.html` はブラウザウィンドウごとに 1 つ読み込まれるため、mod もウィンドウの数だけ動く。`chrome.tabs` のイベントは全ウィンドウ分が届くので、各 mod は自分のウィンドウ（`chrome.windows.getCurrent` で取得し、`tab.windowId` と比べる）のタブだけを扱う。拡張機能ではワークスペースを操作できないため、mod を選ぶ。

**リポジトリ構成（案）**

```
vivaldi-workspace-router/
  src/
    router.js        # 本体。イベント登録、判定、移動、重複処理
    matcher.js       # 純粋関数。タイトル+URL → 移動先候補
    normalize.js     # 純粋関数。URL → 重複判定キー
    config.js        # 既定の設定（public なので顧客名は書かない）
    config.local.js  # 自分の別名と設定。Git に入れず、ビルド時に config.js を上書きする
  build.sh           # src を 1 ファイルに結合して dist/ へ
  install.sh         # dist を Vivaldi に配置し window.html を書き換える
  test/              # matcher / normalize の単体テスト（Node）
```

matcher と normalize は Vivaldi に依存しない純粋関数にして、Node で単体テストできるようにする。`src/` の各ファイルは ES モジュール（`export`）で書き、`build.sh` が `import` / `export` を取り除いて 1 ファイルに結合する。Vivaldi 固有の API 呼び出しは router.js に閉じ込め、API が変わったときの修正範囲を最小にする。

**使う API（実装前に実機で確認、「検証事項」参照）**

- イベント: `chrome.tabs.onCreated`、`chrome.tabs.onUpdated`（`url` / `title` / `status` の変化）
- ワークスペース一覧: 設定値 `vivaldi.workspaces.list`（`vivaldi.prefs.get` で取得）。戻り値は `{ value, defaultValue, store }` で、一覧は `.value`（要素は `{ id: number, name, icon }`）。`vivaldi.prefs.onChanged` の通知の中身は確認できなかったため購読せず、判定のたびに読み直す
- タブの所属: タブの拡張データ（`vivExtData` の JSON 文字列）内の `workspaceId`（number）
- 移動: `chrome.tabs.update(tabId, { vivExtData })` で `workspaceId` を書き換える

## 振り分けロジック

判定は「対象外チェック → キーワード一致 → 一致数で分岐」の順で、一致がちょうど1件のときだけ動かす。

**判定のタイミング**

- タブ作成時と、URL またはタイトルが変わったとき。
- Salesforce Lightning や Slides はロード後にタイトルが確定するので、同じタブへの連続イベントは 800ms 程度デバウンスしてまとめて判定する。
- 自動移動の対象は「作成またはナビゲーションから 30 秒以内」に限る。作業中のタブが、ページ内のタイトル更新（未読数など）で突然移動するのを防ぐ。

**対象外（即終了）**

- 通常ウィンドウ以外（`window.type` が `normal` でないもの。アプリウィンドウ、ポップアップ、DevTools）
- ウェブパネル。通常ウィンドウのタブとして見えるため、`vivExtData.panelId` を持つタブとして除外する
- ピン留めタブ、`vivaldi://` / `chrome://` / `chrome-extension://` のページ
- 手動移動済みフラグが立っているタブ（F6）
- 自分のウィンドウ以外のタブ（ほかのウィンドウの mod が扱う）
- 一時停止中（F8）

**キーワード一致**

- 各ワークスペースのキーワード = ワークスペース名 + 設定の別名。対象はアクティブな全ワークスペース。
- 比較前に両者を正規化する：NFKC（全角英数を半角に）、小文字化、「株式会社」「(株)」など法人格の除去。
- 英字キーワードは単語境界で一致（`ABC` が `ABCD` に当たらないように）。日本語キーワードは部分一致。
- キーワードが `url:` で始まる別名は URL にだけ照合する（例: Celonis のスペース ID、SFDC の商談 ID）。タイトルに顧客名が出ないページの救済策。Celonis のアプリはタイトルが `Celonis | Apps` 固定で顧客名が入らないため、この `url:` 別名が必須になる（`docs/findings.md` #8）。
- 短いキーワードは誤爆防止のため無視し、起動時に警告ログを出す。英字だけのキーワードは 3 文字未満、日本語を含むキーワードは 2 文字未満を無視する（2 文字の日本語の社名があるため）。
- 一方の名前がもう一方に含まれる案件（例：「帝都」と「帝都物流」）は、長い方を優先する。短いキーワードの一致が、別のワークスペースのより長いキーワードの一致の内側にしかなければ、短い方は一致に数えない。短い名前が単独でも出ていれば両方に一致し、2 件以上として扱う。タイトルと URL は別々に判定する。

**一致数での分岐**

| 一致 | 動作 |
| --- | --- |
| 0 件 | 何もしない（今のワークスペースに残る） |
| 1 件、すでにそのワークスペース | 重複処理だけ行う |
| 1 件、別のワークスペース | 移動 → 重複処理 → 設定に応じて移動先へ切替 |
| 2 件以上 | 動かさない。候補名をコンソールに出す。タイトル先頭に「?」を付ける処理は、ページのタイトルを書き換える API が UI から使えるか未確認のため保留（`chrome.tabs` に `executeScript` がない。`docs/findings.md`） |

**手動移動の検出（F6）**

mod が移動した直後の `workspaceId` をタブごとに記録する。以後その値と違う `workspaceId` を検出したらユーザーの手動移動とみなし、そのタブには以降触らない。検出には `chrome.tabs.onUpdated` の `changeInfo.vivExtData` を使う。新しいタブの作成直後にも `vivExtData` だけの通知が来るため、キーの有無ではなく `workspaceId` の値が変わったかで判断する。フラグは `vivExtData` 内に独自キーで持たせ、再起動後も残す。

## 重複タブ処理

移動先ワークスペースに同じ重複キーのタブがあれば、新しい方を閉じて既存タブをアクティブにする。既存タブがハイバネート中ならそのまま前に出せば再読み込みされる。

重複キーは URL をそのまま比べず、サービスごとに「同じものを指す部分」だけに正規化する。

| サービス | URL の例 | 重複キー |
| --- | --- | --- |
| Google Slides / Docs / Sheets | `docs.google.com/presentation/d/<id>/edit#slide=...` | 種類 + `<id>`（`#slide=` や `/edit` は無視） |
| Salesforce Lightning | `*.lightning.force.com/lightning/r/Opportunity/<id>/view` | オブジェクト種別 + レコード ID（15/18 桁は先頭 15 桁で比較） |
| Celonis | `<team>.<region>.celonis.cloud/package-manager/ui/views/ui/spaces/...` | ホスト + パスのリソース ID 部分。ID がないとき（スペース一覧など）は重複処理しない。振り分けは、タイトルに顧客名が出ないので `url:` 別名（URL の中の案件ごとに異なる部分）を使う |
| その他 | 任意 | `#` 以降と `utm_*` 等の追跡パラメータを除いた URL |

安全策として以下を守る。

- 閉じるのは「今 mod が判定している新しいタブ」だけ。既存タブは閉じない。
- わざと開いたとみなせる重複は閉じない。(1) 重複の相手が、そのタブを開いた元のタブ自身のとき（「タブを複製」やページ内のリンク）。(2) 同じページを重複として閉じてから `dedupeReopenGraceMs`（既定 60 秒）以内に開き直したとき。Google Drive の画面など、別のタブから開いた重複は閉じる。
- 新しいタブでフォーム入力などが始まっている可能性を避けるため、作成から 30 秒を過ぎたタブは閉じない。
- 重複判定は自分のウィンドウ内の移動先ワークスペースの中だけ。別の案件で同じ資料を意図的に開いているケースは尊重する。
- どのワークスペースにも一致しないタブも、設定 `dedupeUnmatched` が true なら「今のワークスペース内」で重複処理する（既定 false）。

## 設定ファイル仕様

設定は `src/config.js` に JS オブジェクトとして置き、ビルド時に本体と結合する。リポジトリは public なので、顧客名を含む自分の設定は `src/config.local.js`（`.gitignore` 済み）に書き、ビルド時に `config.js` の既定値を上書きする。ワークスペース名がそのままキーワードになるので、別名が不要な案件は設定に書かなくてよい。ただし実機の検証（`docs/findings.md` #8）では、ワークスペース名（日本語）がそのままタイトルに出ることはなく、タイトルには英語名や略称が入っていた。実際には、ほぼすべての案件で英語名や略称を別名に書く前提とする。

```js
export default {
  enabled: true,
  dryRun: true,              // true の間は移動・切替・クローズをせず、判定をログに出すだけ
  switchOnMove: true,        // F7: 移動したら移動先ワークスペースへ切替
  dedupe: true,              // F5: 移動先での重複処理
  dedupeUnmatched: false,    // 一致なしタブも現ワークスペース内で重複処理
  routeWindowMs: 30000,      // 作成/ナビゲーション後、自動移動を許す時間
  debounceMs: 800,
  conflictMarker: '?',
  ignoreWorkspaces: ['個人', 'Inbox'],   // 振り分け先にしないワークスペース
  minKeywordLength: 3,       // 英字だけのキーワードで、これより短いものは無視して警告（法人格を除いた後の文字数）
  minKeywordLengthNonAscii: 2, // 日本語を含むキーワードの最短の長さ
  aliases: {
    // ワークスペース名: 追加キーワード（url: 始まりは URL にだけ照合）
    'サンプル工業': ['Sample Industries', 'SMPL', 'url:space=abc123'],
  },
  debug: false,              // true で判定ログを UI の DevTools コンソールへ
};
```

一時停止（F8）は設定ファイルではなく実行時の状態として持つ。当面は DevTools のコンソールから `workspaceRouter.toggle()` で切り替える。最終的にはQuick Commands から呼べるコマンドかキーボードショートカットで切り替える。mod から Quick Commands への登録が難しければ、アドレスバー横の小さなトグルボタンで代替する。

## インストールとアップデート追従

Vivaldi を更新するとバージョン番号付きのフォルダが新しくなり mod が消えるため、`install.sh` を冪等に作り、更新を検知して自動で走らせる。

**install.sh の動作**

1. `/Applications/Vivaldi.app/Contents/Frameworks/Vivaldi Framework.framework/Versions/` 配下で最新バージョンの `Resources/vivaldi/` を特定する
2. `dist/workspace-router.js` をそこへコピーする
3. `window.html`（なければ `browser.html`）の `</body>` 直前に `<script src="workspace-router.js"></script>` を挿入する。既にあれば何もしない
4. 元の HTML は `.bak` として保存し、`--uninstall` で戻せるようにする
5. Vivaldi 起動中なら「再起動で反映」と通知する（自動再起動はしない）

**更新の検知**

launchd の LaunchAgent で `Versions/` フォルダを `WatchPaths` に指定し、変化したら `install.sh` を実行する。plist の生成と登録も `install.sh --agent` で行う。Hammerspoon のパス監視でも代替できるが、Hammerspoon 非起動時にも動く launchd を優先する。

アプリバンドルへの書き込みには、macOS の「アプリ管理」の許可が要る（`docs/findings.md` #10）。ターミナルに許可を付ければ手動の `install.sh` は通るが、launchd から起動した場合に同じ許可が効くかは未確認（同 I）。効かなければ、更新を検知したら通知だけ出し、ユーザーがターミナルから `install.sh` を実行する形に下げる。

**注意点**

- アプリバンドル内を書き換えるため、macOS の署名検証や「アプリ管理」権限で書き込みが拒否される可能性がある。実機で確認し、拒否される場合はターミナルに必要な権限を付与する手順を README に書く。
- 会社管理の Mac で MDM がアプリ改変を検知・復元する場合は動かない。導入前に社内ポリシーと合わせて確認する。

## 実装前に検証すべき事項

Vivaldi の内部 API は非公開でバージョンごとに変わるため、以下は本実装の前に実機の Vivaldi（UI の DevTools を `vivaldi://inspect/#apps` から開く）で確かめる。結果は `docs/findings.md` に記録する。

- [ ] 現行版で mod を読み込む HTML のファイル名（`window.html` か `browser.html` か）
- [ ] タブの拡張データのプロパティ名（`vivExtData` か `extData` か）と、その中の `workspaceId` の形
- [ ] ワークスペース一覧の設定キーと構造（id、名前、アイコン）
- [ ] `workspaceId` を書き換えたとき、タブバーの表示が即座に追従するか（しなければ移動の公式経路を探す）
- [ ] 別ワークスペースのタブを `chrome.tabs.update({active: true})` したとき、ワークスペースも切り替わるか
- [ ] ハイバネート中のタブでも URL とタイトルが取れるか
- [ ] ウェブパネルとアプリウィンドウを `chrome.tabs` の情報だけで確実に除外できるか
- [ ] 実際のタイトルに顧客名が入るか：Salesforce 商談、Google Slides、Celonis ダッシュボードを各 2〜3 件確認。入らないものは `url:` 別名で救う方針でよいか
- [ ] Celonis の URL 構造（重複キーに使う部分）
- [ ] アプリバンドルへの書き込みが会社の Mac で許可されるか

## テスト計画と受け入れ基準

**単体テスト（Node、CI 不要）**

- matcher: 全角/半角、大文字/小文字、法人格の有無、英字の単語境界、`url:` 別名、一致 0/1/2 件、短すぎるキーワードの無視
- normalize: 「重複タブ処理」の表の各サービスにつき、同一とみなす URL の組と別物とみなす URL の組をそれぞれ 3 件以上

**実機シナリオ（手動）**

| # | 操作 | 期待結果 |
| --- | --- | --- |
| 1 | 案件 A のワークスペースにいる状態で、Slack から案件 B の Slides リンクを開く | B へ移動し、B に切り替わる |
| 2 | 1 と同じリンクをもう一度開く | 新しいタブは閉じ、B の既存タブが前に出る |
| 3 | 同じ Slides を `#slide=` 違いで開く | 2 と同じ |
| 4 | 顧客名を含まない社内資料を開く | 動かない |
| 5 | A と B 両方の名前を含む資料を開く | 動かず、タイトルに「?」が付く |
| 6 | 1 で移ったタブを手で A に戻し、ページ内を操作する | A に留まる |
| 7 | Salesforce の商談ページを開き、タイトルが遅れて確定する | 確定後に正しく移動する |
| 8 | Gmail アプリやウェブパネルで顧客名を含むページを表示する | 何も起きない |
| 9 | 50 タブを一括で復元して起動する | 既存タブは動かず、CPU が張り付かない |
| 10 | Vivaldi をアップデートする | 自動で再インストールされ、再起動後に動く |

シナリオ 9 のため、起動直後に既にあるタブは対象外とし、mod の読み込み後に作成・ナビゲートされたタブだけを扱う。

**受け入れ基準**

- 上記 10 シナリオがすべて期待どおり
- 1 週間の実務利用で、誤った移動が手で直すのも苦にならない程度（目安: 1 日 2 回以内）

## Claude Code への指示

リポジトリは `moridonut/vivaldi-workspace-router`（public）。この設計書を `docs/design.md` として置き、次の順で進める。各フェーズの終わりで一度止まって結果を報告すること。

1. **検証（Spike）**: 「実装前に検証すべき事項」を、UI の DevTools で貼り付けて実行できる小さなスニペットとして用意し、ユーザーに実行してもらう。結果を `docs/findings.md` にまとめ、設計と食い違う点があれば設計を更新してから先へ進む。
2. **純粋ロジック**: `matcher.js` と `normalize.js` をテスト先行で実装。`node --test` で全部通ること。
3. **router 本体**: イベント登録、デバウンス、対象外判定、移動、重複処理、手動移動の検出。まず `debug: true` かつ「移動しないでログだけ出す」ドライランモードを付け、実機で判定が正しいことを確認してから実際に動かす。
4. **インストーラ**: `build.sh`、`install.sh`（`--uninstall`、`--agent`）、LaunchAgent plist。
5. **README**: 導入手順、設定の書き方、アンインストール、既知の制約。
